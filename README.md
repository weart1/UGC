# UGC-агент

Генерирует вертикальные UGC-ролики по брифу продукта и, при желании, по ролику-примеру.
Все модели работают через [Runware](https://runware.ai): LLM пишет сценарий, Nano Banana делает кадры, Seedance их оживляет. Сборку делает ffmpeg.

```
пример (видео/текст) ─► разбор структуры (caption-модель + LLM)
бриф продукта ────────► сценарий (LLM, JSON: сцены по 4–10 с)
                         ├─► персонаж (Nano Banana) — одно лицо на весь ролик
                         ├─► кадр на каждую сцену (Nano Banana, референсы: персонаж + фото продукта)
                         ├─► клип на каждую сцену (Seedance, image-to-video от кадра)
                         ├─► озвучка (TTS одним куском, чтобы голос не менялся)
                         └─► сборка 1080×1920: склейка, голос, музыка, субтитры, плашки
```

## Быстрый старт

Нужны Node 22+, pnpm и ffmpeg.

```bash
pnpm install
cp .env.example .env              # впиши RUNWARE_API_KEY

# сначала только сценарий, чтобы проверить его до трат на видео
pnpm ugc new examples/serum/brief.json --until script

# дальше весь ролик
pnpm ugc resume runs/<id>

# сделать «как в этом ролике»
pnpm ugc new examples/serum/brief.json --example ref.mp4 [--transcript ref.txt]
```

Готовый ролик лежит в `runs/<id>/final.mp4`. Флаг `--dry-run` прогоняет весь пайплайн на заглушках: без ключа и без трат.

## Как управлять результатом

- **Правка сценария.** Отредактируй `runs/<id>/script.json` и запусти `resume`. Перегенерируются только сцены, которые реально изменились:
  - поменял `visual`, `shot` или `showsProduct` → новый кадр и клип;
  - поменял `motion`, `duration` или `line` → только клип;
  - поменял реплики → новая озвучка;
  - поменял `persona` → всё заново.
- **Не понравилась сцена:** `pnpm ugc redo runs/<id> --stage clips --scene 3`. Для нового кадра вместо клипа — `--stage keyframes`.
- **Статус запуска:** `pnpm ugc show runs/<id>`.
- **Прерванный запуск** продолжается через `resume` с того места, где остановился. Уже оплаченные генерации не повторяются.

## Бриф

Пример: `examples/serum/brief.json`. Поля:

| Поле | Что это |
|---|---|
| `product.name`, `product.description` | что рекламируем |
| `product.images` | реальные фото продукта (пути относительно брифа). Очень желательно: без них модель придумает упаковку сама |
| `offer`, `goal`, `audience` | оффер, целевое действие, ЦА |
| `persona` | как должен выглядеть креатор |
| `personaImage` | готовое фото креатора вместо генерации |
| `format` | формат, если нет примера: «распаковка», «3 причины», «до/после» |
| `targetSeconds` | желаемая длина |
| `music` | фоновая музыка (зацикливается, громкость задаётся в конфиге) |

## Конфиг моделей: `ugc.config.json`

| Слот | По умолчанию | Зачем |
|---|---|---|
| `llm` | `google:gemini@3.5-flash` | разбор примера и сценарий |
| `caption` | `runware:152@2` (Qwen2.5-VL 7B) | описание кадров ролика-примера |
| `image` | `google:4@2` (Nano Banana Pro) | персонаж и кадры. Альтернативы: `google:4@3` (Nano Banana 2), `google:nano-banana@2.1` |
| `video` | `bytedance:seedance@2.5` | клипы. Подешевле: `bytedance:seedance@2.0-fast` |
| `tts` | `alibaba:qwen@3-tts-1.7b-voicedesign` | голос «по описанию» |

`params` в каждом слоте глубоко подмешивается в запрос к Runware. Так можно поменять параметры модели без правки кода, например `{"providerSettings": {...}}`. Значение `null` удаляет ключ из запроса.

`validateParams: true` включает проверку параметров по схеме модели прямо в SDK. Если параметр не подходит модели, запрос упадёт с понятной ошибкой ещё до оплаты.

Режимы звука (`audio`):
- `tts` — закадровый голос одним куском и субтитры. Самый предсказуемый вариант.
- `native` — реплика уходит в промпт видеомодели, и персонаж говорит сам, с липсинком. Звук в Seedance включается параметрами модели: добавь нужный флаг в `models.video.params` по документации модели на Runware.
- `none` — без звука, только субтитры (музыка из брифа всё равно добавляется).

## Что проверить при первом живом запуске

Код написан по типам официального SDK `@runware/sdk`, но живые запросы из среды разработки сделать не удалось. Проверь по документации моделей в кабинете Runware:
1. Размеры `image.width/height` (768×1376) и `video.width/height` (704×1248) под 9:16 для выбранных моделей.
2. Формат референсов: `inputs.referenceImages` для Nano Banana и `inputs.frameImages[{image, frame:"first"}]` для Seedance.
3. Параметры TTS: `positivePrompt` и `speech: {text, voice: "design"}`.

Если что-то отличается, поправь `params` в конфиге: валидация SDK подскажет, какой параметр не так.

## Разработка

```bash
pnpm typecheck
pnpm test        # юнит-тесты + офлайн-прогон всего пайплайна на заглушках
```

Структура: `src/stages/*` — этапы, `src/prompts.ts` — все промпты, `src/gen/runware.ts` — клиент Runware, `src/gen/fake.ts` — заглушки для `--dry-run` и тестов, `src/state.ts` — состояние запуска и инвалидация.
