# UGC Studio

Агент, который по ролику-примеру делает пачку UGC-вариаций для рекламы приложения или товара. Креатор говорит в кадре сам, с липсинком. Работает через веб-панель на твоём сервере, генерации идут через [Runware](https://runware.ai).

```
пример (ссылка или файл) ─► расшифровка речи + кадры ─► разбор структуры (LLM)
бриф + скриншоты + записи экрана
        │
        ▼  для каждой вариации: свой хук и свой креатор
  сценарий (LLM) ──────────────► ⏸ одобрение сценария
  персонаж + кадры (Nano Banana) ► ⏸ одобрение кадров
  клипы (Seedance, черновик) ──► сборка: склейка, вставки записи экрана, субтитры, музыка
        │
        └─ «Сделать финал» → клипы заново на дорогой модели в 1080p, те же кадры
```

## Запуск на сервере

Нужен VPS с Docker (2 ядра, 4 ГБ ОЗУ хватит).

```bash
git clone https://github.com/weart1/UGC && cd UGC
cp .env.example .env     # впиши RUNWARE_API_KEY и PANEL_PASSWORD
docker compose up -d --build
```

Панель слушает только `127.0.0.1:3000`. Есть два варианта доступа:
- **HTTPS с доменом.** Направь A-запись домена на сервер, впиши `DOMAIN=ugc.example.com` в `.env` и запусти `docker compose --profile https up -d`. Сертификат Caddy получит сам.
- **SSH-туннель.** `ssh -L 3000:localhost:3000 user@server`, потом открой http://localhost:3000.

Все данные (проекты, загрузки, ролики) лежат в `./data`. Для бэкапа достаточно копировать эту папку.

## Работа в панели

1. **«Новый проект».**
   - Пример: ссылка на TikTok/Reels/Shorts или mp4.
   - Число вариаций.
   - Продукт: описание, скриншоты приложения, записи экрана.
   - Аудитория и оффер.
2. Агент скачивает пример, расшифровывает речь, разбирает структуру и пишет сценарий для каждой вариации. Каждой вариации даётся свой хук и свой креатор.
3. **Сценарий.** Правишь реплики, кадры и вставки записи экрана, потом жмёшь «Одобрить». Если вариаций много, на странице проекта есть кнопка «Одобрить сценарии» для всех сразу.
4. **Кадры.** Смотришь персонажа и кадры. Любой можно перегенерировать кнопкой «Заново» или сменить персонажа целиком. Потом жмёшь «Одобрить кадры». Видео дальше генерируется по этим кадрам.
5. **Черновик.** Агент собирает ролик на быстрой модели. Неудачный клип можно перегенерировать отдельно.
6. **«Сделать финал».** Для удачных черновиков клипы перегенерируются на финальной модели в 1080p.

### Что задаётся в новом проекте

- **Креатор.** Можно загрузить 1–3 фото-референса. Режим «тот же человек» делает одно лицо во всех вариациях. Режим «похожий типаж» делает другое лицо в том же стиле. Плюс выбор пола, возраста и места съёмки, свободное описание образа.
- **О чём ролик.** Поле «о чём рассказывает креатор» работает в двух режимах:
  - тезисы — агент перескажет своими словами;
  - готовый текст — креатор говорит дословно, текст только разбивается на сцены.
  Ещё выбираются тон и тип хука.
- **Настройки генерации** (только для этого проекта, поверх `ugc.config.json`):
  - язык и режим звука;
  - модели для сценария и кадров;
  - модель и разрешение видео отдельно для черновика и финала;
  - субтитры;
  - на каких шагах ждать одобрения.

Если правишь сценарий после генерации, заново делаются только затронутые сцены:
- кадр, камера или «продукт в кадре» → новый кадр и клип;
- реплика, движение или длительность → новый клип;
- вставка записи экрана или текст на экране → только пересборка, без генераций.

## Приложение в ролике

Есть два способа показать приложение:
- **Записи экрана** (загружаются в проект). LLM видит их описание и ставит в сцену демонстрации:
  - `full` — запись на весь кадр, креатор продолжает говорить за кадром;
  - `pip` — запись окном поверх креатора.
  Интерфейс остаётся настоящим, пиксель в пиксель.
- **«Телефон в руке».** Nano Banana рисует креатора с телефоном, на экране твой скриншот (он передаётся референсом). Интерфейс может слегка исказиться, поэтому для крупных демонстраций лучше записи экрана.

## Модели: `ugc.config.json`

| Слот | По умолчанию | Зачем |
|---|---|---|
| `llm` | `google:gemini@3.5-flash` | разбор примера, сценарии |
| `caption` | `runware:152@2` (Qwen2.5-VL 7B) | описание кадров примера и записей экрана |
| `image` | `google:4@2` (Nano Banana Pro), 768×1376 | персонаж и кадры |
| `video.draft` | `bytedance:seedance@2.0-fast`, 720p | черновики |
| `video.final` | `bytedance:seedance@2.5`, 1080p | финал |
| `tts` | `alibaba:qwen@3-tts-1.7b-voicedesign` | только при `"audio": "tts"` |

- **`params`** в каждом слоте глубоко подмешивается в запрос к Runware. Значение `null` удаляет ключ из запроса.
- **`validateParams: true`** проверяет параметры по схеме модели прямо в SDK. Неверный параметр падает с понятной ошибкой ещё до оплаты.
- **`audio`:**
  - `native` — Seedance генерирует речь и липсинк, в запрос уходит `settings.audio: true`;
  - `tts` — закадровый голос;
  - `none` — без звука.
- **`approvals`** — где агент останавливается. `false` отключает остановку.
- **`language`** — язык реплик и субтитров (`en`). Промпты к моделям картинок и видео всегда на английском.

## Что проверить при первом живом запуске

Код написан по типам официального SDK `@runware/sdk` и документации моделей. Живые запросы из среды разработки сделать не удалось. Поэтому начни с проекта на одну вариацию и проверь:
1. **Звук у Seedance.** Флаг `settings.audio` взят из документации Seedance 2.0. Если 2.5 ругается на этот параметр, звук там задаётся промптом: убери флаг через `"params": {"settings": null}`.
2. **`resolution`** у `video.draft` и `video.final`. Для 2.0-fast может не быть 1080p, для черновика стоит 720p.
3. **Расшифровка примера.** Модель whisper скачивается при первом запуске в `data/.models`, это около 150 МБ для `base`.

## CLI (без панели)

```bash
pnpm install
pnpm ugc new examples/app/brief.json --example https://www.tiktok.com/... --variants 3
pnpm ugc show data/projects/<id>
pnpm ugc approve data/projects/<id> 1 script
pnpm ugc approve data/projects/<id> 1 keyframes
pnpm ugc redo data/projects/<id> 1 --stage clips --scene 3
pnpm ugc final data/projects/<id> 1
```

Флаг `--dry-run` или `DRY_RUN=1` для панели прогоняет всё на заглушках, без ключа и трат.

## Разработка

```bash
pnpm typecheck
pnpm test                                  # юнит-тесты + офлайн-прогон проекта и API панели
DRY_RUN=1 PANEL_PASSWORD=dev pnpm ugc serve
```

Структура кода:
- `src/project.ts` — разбор примера и записей экрана, вариации;
- `src/pipeline.ts` — этапы и точки одобрения;
- `src/stages/*` — генерация и сборка;
- `src/prompts.ts` — все промпты;
- `src/server/*` — API панели, очередь, авторизация;
- `web/` — интерфейс, обычный JS без сборки;
- `src/gen/fake.ts` — заглушки для `--dry-run` и тестов.
